## UI — 接口配置

### UI-1: CLI / Show 命令

- **检查内容**: 功能是否需要新增或修改 CLI 配置命令和 show 命令
- **适用条件**: 所有涉及用户可见配置或状态查询的功能
- **说明**: CLI 完整链路为 AliNOS CLI（sonic-cli 仓库）→ sonic-utilities → CONFIG_DB。新增 CLI 命令需同时评估 sonic-cli（用户界面、参数校验、帮助文本）和 sonic-utilities（实际配置写入）两个仓库的修改；需同步更新命令帮助文本

### UI-2: YANG Model 适配

- **检查内容**: 是否需要新增或修改 YANG model 定义
- **适用条件**: 涉及 Config DB 表结构变更、新增配置项时
- **说明**: YANG model 是 SONiC 配置校验的基础，必须与 CLI/Config DB 保持一致

### UI-3: Telemetry 白名单

- **检查内容**: 功能配置是否需要通过 Telemetry GRPC 下发，是否已加入白名单
- **适用条件**: 需要通过 Telemetry 通道下发配置的功能
- **说明**: 未加入白名单的配置会被 Telemetry 模块拒绝；白名单配置方式参见团队 Telemetry 文档

## SPEC — 功能规格

### SPEC-1: 功能点与原始需求

- **检查内容**: 明确列出所有功能点，并与原始需求逐条对应
- **适用条件**: 所有功能开发
- **说明**: 需提供原始需求链接；功能点需在测试文档中逐一覆盖

### SPEC-2: 规格与性能

- **检查内容**: 明确功能的预期规格上限和性能指标
- **适用条件**: 所有功能开发
- **说明**: 如最大邻居数、最大路由条目数、收敛时间等

### SPEC-3: 支持角色

- **检查内容**: 明确功能支持的设备角色
- **适用条件**: 所有功能开发
- **说明**: DC 网络角色包括 ASW(ToR)、PSW(Leaf)、DSW(Spine)、MA、DCC、MC 等

### SPEC-4: 支持平台与版本

- **检查内容**: 明确功能支持的硬件平台和软件版本范围
- **适用条件**: 所有功能开发
- **说明**: 需注明芯片平台（如 memory/th5 等）和起始支持版本

### SPEC-5: 基础配置与动态修改

- **检查内容**: 确认功能配置是基础配置还是动态配置，是否允许运行时修改
- **适用条件**: 涉及配置项的功能
- **说明**: 基础配置通常在设备启动时加载；动态配置需支持运行时生效和回退

### SPEC-6: 回退能力

- **检查内容**: 功能是否具备关闭/回退能力，关闭后是否无残留配置和状态
- **适用条件**: 所有功能开发
- **说明**: 回退指功能级别的关闭，包括配置清理、状态清理、资源释放

### SPEC-7: 限制与约束

- **检查内容**: 明确功能的已知限制、与其他功能的互斥关系
- **适用条件**: 所有功能开发
- **说明**: 如 advertise-delay-onstartup 与 advertise-delay 不可同时配置

## PROC — 进程与可观测性

### PROC-1: 进程管理

- **检查内容**: 新增进程是否配置了 logrotate、进程退出告警、supervisor 管理
- **适用条件**: 新增独立进程时
- **说明**: log 文件必须配置 logrotate 防止磁盘占满；进程异常退出需触发告警

### PROC-2: 日志规范

- **检查内容**: 初始化阶段是否有 NOTICE 级别日志，运行时日志是否会频繁刷屏
- **适用条件**: 所有涉及日志输出的功能
- **说明**: 关键路径需有 DEBUG 日志便于问题定位；避免在数据面热路径中打印高频日志

### PROC-3: 内存使用评估

- **检查内容**: 功能的内存使用量是否做过评估，对系统整体内存的影响
- **适用条件**: 功能涉及大规模数据缓存、新增进程、或路由/表项规模较大时
- **说明**: 需评估最大规格下的内存占用；关注是否对路由收敛性能有影响

## SCENARIO — 异常场景

<!-- 以下 15 个场景需逐一评估是否适用于当前功能。

### SCENARIO-1: 进程异常重启

- **检查内容**: 功能进程异常重启后，功能是否自动恢复到正确状态
- **适用条件**: 功能涉及独立进程或依赖的进程可能重启时
- **说明**: 包括 OOM kill、signal kill 等场景；需验证状态机和数据一致性

### SCENARIO-2: 接口 Down/Up

- **检查内容**: 物理接口 down 再 up 后，功能状态是否正确恢复
- **适用条件**: 功能涉及物理接口或依赖接口状态时

### SCENARIO-3: 子接口扩缩容

- **检查内容**: 子接口动态增加或删除时，功能是否正确处理
- **适用条件**: 功能涉及子接口或 VLAN 子接口时

### SCENARIO-4: 路由隔离

- **检查内容**: VRF 或路由隔离场景下，功能是否正确隔离，不发生跨域泄漏
- **适用条件**: 功能涉及路由处理且部署环境存在多 VRF 时

### SCENARIO-5: LACP 隔离 / Shut 所有下连口

- **检查内容**: LACP 成员全部隔离或所有下连口 shut 后，功能行为是否正确
- **适用条件**: 功能涉及 LAG 接口或下连端口时

### SCENARIO-6: BGP 扩缩容

- **检查内容**: BGP 邻居动态增加或删除时，功能是否正确响应
- **适用条件**: 功能涉及 BGP 协议或依赖 BGP 邻居状态时

### SCENARIO-7: 路由震荡

- **检查内容**: 大规模路由频繁更新（震荡）时，功能是否稳定，不引发资源耗尽
- **适用条件**: 功能涉及路由处理时

### SCENARIO-8: 接口震荡

- **检查内容**: 接口频繁 down/up 时，功能是否稳定，不产生状态不一致
- **适用条件**: 功能涉及接口状态监听时

### SCENARIO-9: 邻居震荡

- **检查内容**: BGP/协议邻居频繁建立和断开时，功能是否稳定
- **适用条件**: 功能涉及协议邻居关系时

### SCENARIO-10: MAC 震荡

- **检查内容**: MAC 地址频繁迁移时，功能是否正确处理，不引发环路
- **适用条件**: 功能涉及 L2 转发或 MAC 学习时

### SCENARIO-11: BMC 掉电

- **检查内容**: BMC 掉电恢复后，功能是否正常，不依赖 BMC 持续供电
- **适用条件**: 功能涉及 BMC 交互或硬件管理时

### SCENARIO-12: 磁盘更换

- **检查内容**: 磁盘更换后，功能配置和状态是否能正确恢复
- **适用条件**: 功能数据持久化到磁盘时

### SCENARIO-13: 插拔光模块

- **检查内容**: 光模块热插拔时，功能是否正确处理接口状态变化
- **适用条件**: 功能涉及物理接口且部署环境使用可插拔光模块时

### SCENARIO-14: Reboot / 打补丁

- **检查内容**: 设备 reboot 或容器打补丁重启后，功能是否正确恢复
- **适用条件**: 所有功能开发
- **说明**: 包括整机 reboot 和容器级别的补丁重启（容器重启时配置需持久化）

### SCENARIO-15: Warm Boot

- **检查内容**: Warm Boot 过程中功能是否保持数据面不中断，重启后状态一致
- **适用条件**: 功能涉及数据面转发且部署环境启用 Warm Boot 时
- **说明**: Warm Boot 要求控制面重启期间数据面零丢包

## CODE — 代码质量

### CODE-1: 内存管理

- **检查内容**: 是否使用 malloc/calloc 等手动内存分配，是否有对应的释放逻辑
- **适用条件**: C/C++ 代码中使用手动内存管理时
- **说明**: 优先使用智能指针或 RAII 模式；检查所有异常路径是否有内存泄漏

### CODE-2: 多线程与锁

- **检查内容**: 是否使用多线程，锁的粒度是否合理，是否存在死锁风险
- **适用条件**: 代码涉及多线程或并发访问共享资源时
- **说明**: 注意锁的获取顺序一致性；避免在持锁期间进行耗时操作

### CODE-3: 未初始化变量

- **检查内容**: 是否存在未初始化的变量，特别是在条件分支和错误路径中
- **适用条件**: C/C++ 代码开发时
- **说明**: 编译器 `-Wall -Werror` 可辅助检测；重点关注局部变量和结构体成员

### CODE-4: 单元测试覆盖率

- **检查内容**: sonic-swss、sonic-swss-common、sonic-sairedis 和 Go/Python 代码是否添加单元测试
- **适用条件**: 上述仓库的代码变更
- **说明**: 新增代码行覆盖率需超过 90%，函数覆盖率目标 100%
